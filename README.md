# Сопоставление таможенных деклараций и регуляций

Для каждой декларации возвращаются 10 наиболее релевантных регуляций.

## 1. Установка и запуск

```bash
pip install -r requirenments.txt
python run.py --data ./data --out ./out
```

Векторный индекс FAISS уже лежит в `data/`, его **не нужно пересоздавать** (`python make_vectors.py` и шаг `make_vectors` внутри `run.py` пропускаются, если файлы индекса на месте).

Результат: `out/predictions.csv`  
колонки: `declaration_id, rank, regulation_id, score`  
для каждой декларации ровно 10 уникальных регуляций, ранги 1–10, больший `score` — выше релевантность.

Разбор пяти деклараций с самым слабым top-1 скором: `[анализ_ошибок.md](анализ_ошибок.md)`.

## 2. Переменные `.env`


| Переменная           | Назначение                                                                                 |
| -------------------- | ------------------------------------------------------------------------------------------ |
| `EMBEDDING_MODEL`    | Модель эмбеддингов для чанков ТН ВЭД и retrieval (`BAAI/bge-m3`)                           |
| `RERANKER_MODEL`     | CrossEncoder для финального скоринга пары декларация–регуляция (`BAAI/bge-reranker-v2-m3`) |
| `DECLARATIONS_JSONL` | Входной файл деклараций                                                                    |
| `REGULATIONS_JSONL`  | Входной файл регуляций                                                                     |
| `DECS_DATA_OUT_NAME` | Промежуточный JSON: важные поля из деклараций + `retrieved_context`                        |
| `INDEX_NAME`         | Файл FAISS-индекса чанков `tnved_knowledge.txt`                                            |
| `CHUNKS_NAME`        | JSON с текстами чанков, соответствующих векторам в FAISS                                   |
| `CHUNK_SIZE`         | Размер чанка при нарезке справочника                                                       |
| `CHUNK_OVERLAP`      | Перекрытие соседних чанков                                                                 |
| `BATCH_SIZE`         | Размер батча                                                                               |
| `TOP_K_FRAGMENTS`    | Сколько наиболее релевантных чанков ТН ВЭД подтянуть к декларации                          |




## 3. Подход и пайплайн

Retrieval + CrossEncoder rerank. LLM не классифицирует код ТН ВЭД.

```
declarations.jsonl + tnved_knowledge (FAISS)
        ↓
1. extract_declarations — G31_1, desc_extention
        ↓
2. retrieve_context — BGE-M3 + FAISS → top-k фрагментов ТН ВЭД в retrieved_context
        ↓
3. rerank_regulations — CrossEncoder(декларация+контекст, регуляция) → top-10
        ↓
out/predictions.csv
```

`make_vectors.py` режет `tnved_knowledge.txt`, считает эмбеддинги BGE-M3 и пишет FAISS.

## 4. Преимущества выбранного пайплайна

- LLM не принимает финальное решение. Он (и encoder-модели вокруг текста декларации) делает то, в чём полезен: извлекает признаки и интерпретирует формулировки декларации. Итоговый код выбирает не генерация, а скоринг пар.
- `tnved_knowledge.txt` используется адресно: в контекст декларации попадают только top-k релевантных чанков из FAISS, а не весь справочник в prompt.
- Финальное ранжирование делает CrossEncoder (`bge-reranker-v2-m3`): он смотрит на пару «декларация + регуляция» целиком и оценивает релевантность, а не только косинус эмбеддингов.



## 5. Альтернативы


| Pipeline       | Как работает                               | Преимущества                                    | Недостатки                                                 |
| -------------- | ------------------------------------------ | ----------------------------------------------- | ---------------------------------------------------------- |
| **Baseline 1** | BGE-M3 cosine → Top10                      | Максимально простой и быстрый                   | Слабее понимает точные термины и тонкие различия регуляций |
| **Baseline 2** | BGE-M3 + BM25 + RRF → Top10                | Учитывает и смысл, и точные совпадения          | Всё ещё нет глубокого сравнения declaration ↔ regulation   |
| **Baseline 3** | BGE-M3/BM25 → Top50 → CrossEncoder → Top10 | Значительно более точное финальное ранжирование | Сложнее и вычислительно дороже                             |
